# Real DBMS guidance execution: exploratory results and stop/go decision

This is an operational proxy study on real JDBC SQLite, **not** a validated Paper 3 forecast, a Paper 4 action-utility estimate, an AI-agent trial, or a distinct-bug discovery result. The test choice came from the source-backed DBMS direction dossier in [`cs_direction_shortlist.md`](cs_direction_shortlist.md). All runs used pinned source, NoREC, a fixed seed per pair, one CPU/1 GiB Docker container per condition, and no network. Raw logs and per-run metadata are retained.

## Short paired runs: 10 seeds (4101–4110)

[`results/dbms_guidance_campaign_v3/summary.json`](../results/dbms_guidance_campaign_v3/summary.json) is generated by `scripts/run_dbms_guidance_campaign.py`. Each SQLancer arm allowed one database and 200 NoREC checks; each SQLancer++ arm allowed three databases and 200 checks per database. These are *within-tool* comparisons, not a shared CPU-hour budget or a cross-tool comparison.

- In pinned SQLancer (JDBC SQLite **3.49.1**), 9/10 seed pairs completed a database in both arms. Seed 4109 returned exit code 0 in both arms but completed **zero** databases and zero oracle checks. Its raw trace is retained as a measurement failure, not silently counted as a zero-bug test. On the 9 operational pairs, QPG completed an average of **7.33 more** NoREC checks than unguided (each arm capped at 200). Exactly parsed successful/unsuccessful statement totals exist for 7 pairs; two print compact `1k` totals, so their exact counts are not fabricated.
- In pinned SQLancer++ (JDBC SQLite **3.40.0**), all 10 seed pairs completed three databases. Feedback on/off had identical aggregate completed-query and successful/unsuccessful statement counts in all 10. The retained current-log SQL statement sequences, after removing runtime notes and headers, were identical in all 10 pairs. This says the short setting did not expose an operational difference; it does **not** prove the feedback mechanism ineffective.

## Falsifying the short-run interpretation: 20 databases × 5 seeds

Because the SQLancer++ feedback update occurs after database runs, the three-database null was challenged with a longer, still bounded **within-tool** test. [`results/sqlancerpp_feedback_long_campaign/summary.json`](../results/sqlancerpp_feedback_long_campaign/summary.json), generated by `scripts/run_sqlancerpp_long_campaign.py`, retains five independent seeds (4101–4105), each paired feedback-off/on at 20 databases and a 200-query cap per database. All ten processes completed 20 databases.

The console's overall query count is abbreviated (`2k`), so successful query-pair totals are **inferred** from the 20 per-database `Success rate for query pairs` values times the configured 200 attempts. Every product was integral, and the same calculation agrees with the exact overall count in the three-database runs; the long-run logger does not expose the raw denominator for an independent check, so treat these as derived proxy counts. On that basis, feedback-on minus feedback-off was **+215, +221, +373, +277, +244** successful query pairs; across five seeds, approximately 13,628 versus 12,298, a 1,330-pair difference (about 10.8% of the off total). The result is exploratory: the longer horizon was chosen after seeing the short-run null, five seeds are few, and matched query caps are not a matched CPU-hour budget. It establishes that the toggle can change the observed validity/completion proxy when given more databases, not that it finds more bugs.

## Decision

The **measurement and method-comparison problem is worth one more bounded phase**, not a large AI-agent effectiveness claim. Pre-register a repeated, equal-CPU-hour within-tool study; retain per-database exact counts and normalized SQL traces; measure valid SQL yield and independently reproducible, deduplicated NoREC discrepancies. Add a stop gate: if a proxy gain does not lead to distinct reproducible behaviors or if setup/measurement failures dominate, do not escalate to an agent-level study. The published SQLancer++ and QPG code still cannot support a flag-only 2×2; see [`sqlancerpp_compatibility_audit.md`](sqlancerpp_compatibility_audit.md). No confirmed distinct logic bug was found in these runs.
