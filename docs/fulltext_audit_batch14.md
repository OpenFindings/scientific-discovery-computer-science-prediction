# Full-text audit batch 14 — coordination depends on what is being coordinated

Updated 2026-10-11. Four papers were selected from the predeclared uniform-random `agent_memory_coordination` frame, one per period. Full texts, methods, evaluation tables, counterconditions, and stated limitations were checked. This is a small audit batch, not a prevalence estimate.

## 1. LP-DPOP: constraint structure can help, but representation and problem regime matter

**Sample:** Le et al., [Logic and Constraint Logic Programming for Distributed Constraint Optimization](https://arxiv.org/html/1405.1734v2), arXiv:1405.1734v2. The paper itself is labeled 2013 and the arXiv v2 was posted in 2014; it has a DOI, so this is not clean evidence of a result first invented in 2014. The frame year must not be mistaken for a publication year.

The authors compare ordinary DPOP with two LP-DPOP encodings. On random graphs, the *facts* encoding solves 100% of 50 generated instances at 20 variables, while DPOP solves 0% under a 10-minute timeout; at 15 variables it solves 100% versus 86%, with reported simulated runtimes of 1,008 ms versus 39,701 ms on solved cases. The advantage is not universal: for domain size 12, LP-DPOP-facts solves only 60% (DPOP also solves 0%); at constraint density 0.3, its runtime is 2,629 ms versus DPOP's 286 ms; at tightness 0.4, it is 155,089 ms versus 48,632 ms. On smart-grid cases, the *rules* encoding is strongest, while the facts encoding is slower than DPOP throughout that domain. These are different encodings of the same high-level idea, not one uniformly winning “logic” method.

The comparison uses simulated runtime, one 3.4-GHz quad-core/16-GB machine, synthetic random instances (50 per point), and several smart-grid topologies. The paper calls the work preliminary and explicitly leaves automatic selection of a local solver for each DCOP class open. Therefore it supports a conditional mechanism claim—implicit hard constraints can prune search when the constraint structure and encoding fit—not a general deployment-speed claim.

## 2. TeamReg / CoachReg: predictability and synchronized choices help some sparse-reward tasks

**Sample:** Roy et al., [Promoting Coordination through Policy Regularization in Multi-Agent Deep Reinforcement Learning](https://arxiv.org/html/1908.02269v4), arXiv:1908.02269v4 (2019 submission; v4 in 2020).

I cross-checked the key claims and Table 1 against the [official NeurIPS 2020 proceedings PDF](https://papers.nips.cc/paper_files/paper/2020/file/b628386c9b92481fab68fbf284bd6a64-Paper.pdf); the table values cited below agree. The official paper itself says TeamReg can be harmful when a task has an adversarial component, so the COMPROMISE reversal is not a discrepancy caused by comparing the wrong arXiv revision.

TeamReg regularizes inter-agent action predictability; CoachReg encourages synchronized selection among sub-policies. The test suite uses four continuous-control, sparse-reward particle tasks, plus Google Research Football. The reported main comparison uses 50 hyperparameter configurations × 3 seeds for screening, then the selected configuration is retrained on 10 seeds for twice as long; the authors estimate roughly three CPU-years of experiments.

The table makes the condition visible. TeamReg/CoachReg score 216±12 / 210±12 on SPREAD versus MADDPG's 159±6; and 5.8±1.3 / 7.4±1.2 on BOUNCE versus 4.0±1.6. But on the adversarial COMPROMISE task TeamReg falls to 8.8±0.9 versus MADDPG's 18.1±1.1, while CoachReg reaches 31.1±1.1. On CHASE, all are strong and policy sharing is highest (980±64 versus CoachReg 949±54). So “make agents predictable” is not enough: which regularizer, whether the objective includes adversarial incentives, and whether symmetry is optimal all matter. The paper's authors also report that ordinary MADDPG rarely significantly beats its decentralized DDPG counterpart on these sparse-reward environments unless coordination is explicitly incentivized.

## 3. PAC: counterfactual assistance helps on selected hard cooperative-RL maps, with reproducibility boundaries

**Sample:** Zhou et al., [PAC: Assisted Value Factorisation with Counterfactual Predictions in Multi-Agent Reinforcement Learning](https://arxiv.org/pdf/2206.11420v3), NeurIPS 2022, arXiv:2206.11420v3.

PAC targets a specific failure mode: under partial observability, monotonic value-factorization can impose incompatible action orderings across states. It trains a counterfactual predictor to provide assistance while retaining centralized training/decentralized execution. The evaluated set includes predator-prey and six deliberately difficult StarCraft II micromanagement maps. On the paper's chosen maps, PAC is among the few methods learning usable policies on 3s_vs_5z and 6h_vs_8z; it reports faster convergence and slightly higher performance than selected value-based baselines on corridor. This is not a universal win on all possible coordination tasks: easy maps show smaller gaps, and the suite emphasizes hard exploration/coordination cases.

Important comparison caveat: the paper states that all StarCraft II results use version 2.4.10 and performance is not comparable across versions; PAC is built on an open-source codebase and QMIX/WQMIX results are taken from that codebase. The study uses four random seeds for each baseline. It also reports no strict convergence guarantee, higher variance than value-based methods, and homogeneous parameter sharing that does not test role-specialized agents. The result is a promising intervention for a defined partial-observation/value-factorization setting, not evidence that counterfactual information solves general multi-agent coordination.

## 4. GitHarness: promising evolving-requirement memory, but not multi-agent coordination evidence

**Sample:** Yang et al., [GitHarness: Git Init Your Harness Working Memory for Perpetual User Requirements](https://arxiv.org/pdf/2609.36789v1), arXiv:2609.36789v1 (2026-09-29).

The framework versions user requirements alongside work state, so a single assistant can select compatible past work after a requirement changes. Across five domains, two backbones, and three harnesses, its training-free variant beats native cross-turn execution in all 30 settings and matches or beats the strongest baseline in 28/30. But its seven-turn requirement-change trajectories are generated from public benchmarks with LLM assistance; the authors explicitly say there are no real-user conversations or private data. They also flag ambiguity/conflicting feedback and imperfect preservation of unaffected work as unresolved.

This paper was randomly retrieved through a broad `agent_memory_coordination` label, but it is about one agent collaborating with a human—not coordination among autonomous agents. Count it as a reviewed retrieval false positive / adjacent topic, not as evidence that multi-agent coordination improved. That mismatch is itself useful: keyword/category screens need full-text adjudication, and “memory” should be split into agent-agent coordination versus human-agent evolving requirements.

## Cross-paper synthesis and next test

Three distinct types of work—distributed constraint optimization, sparse-reward MARL, and user-agent requirement tracking—should not be presented as one continuous algorithmic lineage. Within the directly relevant DCOP/MARL sources, however, the recurring empirical pattern is conditional: an explicit coordination signal or a representation that exposes useful constraints can improve selected difficult cases, while its benefit can disappear or reverse when the task has a different constraint regime, adversarial objective, symmetry structure, or evaluation setup. This is a hypothesis suggested by a few heterogeneous experiments, not a pooled effect or a claim of historical prevalence.

**Falsifiable next study:** On a shared, preregistered multi-agent suite, compare (a) no explicit coordination signal, (b) action-predictability regularization, (c) synchronized sub-policy selection, (d) counterfactual joint-action assistance, and (e) constraint-aware/local-solver selection where applicable. Cross each with cooperative versus mixed-motive tasks, symmetric versus role-specialized agents, sparse versus shaped reward, and low/high constraint density. Hold compute/tuning budgets and environment versions fixed, report per-task outcomes and failures (not only aggregate win rate), and reserve unseen task families. The conditional pattern is weakened if one method dominates across the preregistered adverse strata under matched budgets; it is strengthened if rankings systematically reverse with the declared task properties. Test human-agent requirement tracking separately with real longitudinal sessions and audited stale-requirement/regression outcomes; GitHarness's synthetic benchmark cannot answer that deployment question.

## Citation follow-up: a 25-task benchmark independently sharpens the boundary

**Follow-up:** Papoudakis et al., [Benchmarking Multi-Agent Deep Reinforcement Learning Algorithms in Cooperative Tasks](https://arxiv.org/html/2006.07869v3), arXiv v3 (2021). This is a broad comparative study, not a replication of TeamReg or PAC: it benchmarks nine MARL algorithms on 25 tasks across repeated matrix games, particle environments, StarCraft II, Level-Based Foraging, and Multi-Robot Warehouse.

The results support a more precise conditional claim. Centralized training helps on coordination-heavy, partially observable tasks such as Speaker-Listener and hard SMAC; independent learning is competitive on fully observable MPE/LBF tasks. Yet in sparse-reward RWARE, MAA2C/MAPPO improve over their independent counterparts while COMA, VDN, and QMIX show little or no learning. Parameter sharing usually improves average returns outside matrix games, and the benefit appears larger for sparse-reward/larger-grid cases—but some tasks are exceptions, and the paper says the average gains are not clearly statistically significant. The authors tuned on one task per environment family, report five evaluation seeds, and spent 147,032 CPU hours excluding hyperparameter search.

This follow-up supports task observability, reward sparsity, architecture, and implementation as moderators; it does not validate TeamReg/PAC directly because neither is among its nine algorithms. The later paper's algorithm rankings differ substantially from the older algorithm set too: simple IPPO/IA2C can outperform MADDPG/COMA in many tasks. That is a warning against treating a single paper's baseline as a stable field-wide reference.
