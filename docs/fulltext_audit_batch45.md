# Full-text audit batch 45: agent capability scores across operating regimes

Updated 2026-10-12. This batch follows the frozen lexical-priority arm for three papers in `agent_reliability_security` and separately reads one later mobile-agent benchmark cited for a cross-paper comparison. Full arXiv HTML was inspected, including methods/results/limitations; the arXiv IDs, versions, frame status, and source URLs are in `data/fulltext_review_ledger_batch45.jsonl`. This is a purposive batch, not a representative estimate.

## Sampled full texts

1. **AndroidWorld: A Dynamic Benchmarking Environment for Autonomous Agents** (`2405.14573v5`, frame: `agent_reliability_security`, 2020–2024, lexical-priority; [arXiv HTML](https://arxiv.org/html/2405.14573)). The benchmark provides 116 parameterized tasks across 20 Android apps with device-state reward checks (Sections 3.3–3.4). Its M3A baseline reports 30.6% in the initial single-seed benchmark. In the robustness study, the same configuration achieves 27.6%, 26.3%, and 33.2% over three seeds (mean 29.0%); on a representative subset, 20 trials/task compare same-parameter repeatability with changed task parameters. The paper reports greater variance across different task seeds, including significant differences for add-expense and edit-note tasks, and explains concrete causes such as a hidden horizontal-scroll category or a more difficult text-replacement variant (Sections 5, Appendix E.4–E.5). A Pixel 5 / Android 12 check gives 28.4%, but that is one alternate device/OS setup. Limits: the robustness subset is five tasks, compute constrained, and cannot establish full-suite variance or a general agent ranking; apps are open-source or built-in rather than authenticated commercial apps (Appendix A).

2. **Can LLM Agents Be CFOs? Benchmarking Long-Horizon Resource Allocation in an Uncertain Enterprise Environment** (`2603.23638v2`, frame: `agent_reliability_security`, 2025–2026-through-10-11, lexical-priority; [arXiv HTML](https://arxiv.org/html/2603.23638)). EnterpriseArena simulates a single consumer-lending firm for 132 monthly steps; tool access is budgeted, information is partial, and fundraising settlement is delayed. Across 23 backbone LLMs and three additional agent frameworks, 15.4% of trials survive the full horizon; only 13% of ReAct trials do. Even the top reported framework reaches 60% survival but a valuation score far below the human baseline (Table 1; Sections 3–4). The paper's own ablation varies stochasticity, delayed feedback, action exclusivity, and tool budgets (Figure 3). This is evidence about one simulated financial decision process, not readiness for real CFO work. The authors explicitly note Gaussian/regime dynamics omit black-swan events and long funding freezes, the setup is single-agent rather than organizational, and evaluation remains initial (Appendix J). Table cells generally use five runs/model, so small-run uncertainty matters.

3. **Coalition-Aware Skill Reliability for Self-Evolving Agents** (`2608.22610v1`, frame: `agent_reliability_security`, 2025–2026-through-10-11, lexical-priority; [arXiv HTML](https://arxiv.org/html/2608.22610)). The paper tests whether an accumulated skill helps as part of a bank, not just whether the bank-level reward rose when it was added. In one source→target example, a skill has a positive LoCoMo contribution (+0.084 with 95% CI excluding zero) but a negative HotpotQA point estimate (-0.035) whose interval includes zero; the paper correctly calls this a directional reversal, not significant harm (Section 3.3). In the matched MemSkill comparison, the baseline's six accepted additions are collectively -1.38 percentage points versus its fixed-size earlier bank over the reported three-seed experiment; CASS accepts one of 12 proposals (Section 5.3). Across four benchmarks, reported scores improve, but the core matched result is concentrated on the MemSkill setup. The authors report three seeds under a fixed judge, and u-SMCO uses target-domain unlabeled queries and has quadratic memory rebuild cost. The HTML has no dedicated limitations heading; these scope and compute constraints are explicit in its experiment and method sections. Treat the cross-domain reversal example as directional, and seek independent replications before generalizing.

## Out-of-frame comparator (citation follow-up, not a sample draw)

4. **MobileWorld: Benchmarking Autonomous Mobile Agents in Agent-User Interactive and MCP-Augmented Environments** (`2512.19432v3`, [arXiv HTML](https://arxiv.org/html/2512.19432)). This later paper reports 201 tasks across 20 apps, with 62.2% cross-app workflows versus 9.5% in AndroidWorld, and mean completion length 27.8 versus 14.3 steps under its GPT-5 + UI-Ins-7B framework. Its best agentic framework scores 51.7% overall, 62.2% on clarification tasks, and 51.6% on MCP tasks; the best end-to-end model scores 20.9% overall (Sections 3–4, Tables 6–7). This is not a controlled before/after comparison: task distributions, available actions, models/frameworks, and benchmark construction differ. The numerical gap must not be interpreted as capability decay or as evidence that AndroidWorld scores are invalid. MobileWorld's deterministic state/backend checking is a counterpoint to noisy judge-based evaluation, while its authors' claim that AndroidWorld is saturated remains a paper claim, not independently verified here.

## Bounded synthesis and falsifiable next test

Across these papers, benchmark scores are conditional on the operating regime and outcome definition: AndroidWorld demonstrates within-benchmark seed sensitivity; MobileWorld deliberately adds longer cross-app workflows, clarification, and MCP actions; EnterpriseArena measures survival and valuation in a long-horizon simulator; and the skill-bank paper shows that component contribution can change with bank composition and target domain. These are related evaluation cautions, not a pooled effect and not one common construct. The evidence motivates a testable question: **How much do agent rankings and calibrated success estimates change when the same agent versions are evaluated on matched short-horizon, parameter-shifted, long-horizon, cross-app, and tool/clarification tasks with the same scoring rules?**

Preregister the agent set, model versions, task strata, run counts, tool/step budgets, and primary estimand. Evaluate every agent on each stratum with repeated seeds; report per-stratum success and calibration with uncertainty, worst-stratum performance, and rank correlation against the aggregate leaderboard. Add an independent verifier audit for task rewards. The portability hypothesis is weakened if rankings and calibrated success estimates remain stable across strata and an independent rerun. No such common evaluation was run in this batch.
