# 全文审查批次 5：2010–2014 随机样本与一次引用追踪

审查日期：2026-10-11。固定抽样框为 `data/fulltext_stratified_sample.jsonl`；以下前三篇来自 uniform-random arm，而非词法优先组。第四篇是从第一篇的后续文献链追到的 citation follow-up，不计入随机样本覆盖率。

## 1. 一般化故障模型下的迭代近似拜占庭共识（arXiv:1205.4809v1；随机样本）

- 范围：arXiv 2012 上传；后续会议版本发表于 ICDCN 2013。不是实验论文，结论建立在同步、点对点、有向通信图与给定可行故障域上。
- §4，定理 1：每个可行故障集合及其对应的任一 reduced graph 都必须恰有一个 source component，是正确 IABC 算法存在的必要条件。
- §§5–6，算法 1 与定理 2：作者证明该条件也充分。节点按邻居当前值排序，并仅删除可由本地可行故障集合解释的极端值，再对保留值取平均。节点只需知道哪些入邻居可能同时失效，不需要全局获知整个故障域。
- §7：作者强调该刻画覆盖相关故障和非均匀节点可靠性；但文章没有真实网络部署、丢包/异步实验，也没有测量计算和通信开销。
- 审查边界：这是形式化结果，不等于任意现实网络满足条件；“充要”针对论文定义的模型，不应泛化到异步网络、签名/多跳通信或不同故障假设。

## 2. Countering Trusting Trust through Diverse Double-Compiling（arXiv:1004.5548；随机样本）

- 核查 arXiv 论文正文摘要，并对作者公开的完整博士论文逐章定位复核其假设和局限（DDC 详细证明/演示为博士论文材料，故不把它说成 arXiv 短论文中全部内容）。
- DDC 的主张是：用一个独立可信编译器编译被测编译器的父源代码，再用所得编译器编译被测编译器源代码；若结果与被测二进制逐位相同，且形式化假设成立，则被测二进制对应其声称的源代码。
- 博士论文 §7 记载 tcc、小型 Lisp 编译器（含已知恶意版本）和 GCC 演示；§8.1–8.2 列出重要边界：DDC 不证明源代码无恶意/无缺陷，只把审查对象从二进制转回源代码；可信编译器、环境、获取/比较过程也必须可信；非确定性可导致比较失败且难定位。
- 审查边界：这是一个关于特定供应链威胁模型的论证与演示，不是对任意现代工具链的端到端保证。作者公开的后续 GNU Mes 实例也提醒，使用相似 GCC 版本的多个发行版并不等于高度独立的信任根。

## 3. Multiple Frequency Selection in DVFS-Enabled Processors to Minimize Energy Consumption（arXiv:1203.5160v2；随机样本）

版本核对：早期 ledger 曾误记为 v1；抽样框指向 v2。现已直接复核 arXiv v2 PDF 的 §6.1、§6.2 Table 2 与 §7；原有结果与边界确认无误。所用是拟合 Transmeta Crusoe 与 Intel Xscale 的模拟功耗模型，不是实机测量。

- §6.1–6.2：论文以拟合的两款旧处理器功耗—频率模型做调度仿真；包含 1,500 个随机任务图，以及来自 LU decomposition、Gauss–Jordan 的应用任务图。它不是在现代处理器上直接测量能耗。
- Table 2 报告 MFS-DVFS 在随机任务上的节能为 14.40%，连续频率最优基线为 14.84%；LU 为 27.0% 对 27.81%；Gauss–Jordan 则仅 0.11% 对 0.14%。§6.2 将 Gauss–Jordan 表现差归因于任务图没有任务间空闲时间，因而无算法能有效回收 slack。
- 这给摘要中的“几乎达到最优”加上重要条件：相对差距不大，但绝对节能可从 LU 的约 27% 降至 Gauss–Jordan 的约 0.1%。任务结构/可回收 slack 可能比算法名称更决定实际收益。
- 审查边界：模拟器、凸功耗拟合和历史处理器模型限制外推；没有现代硬件的实测、置信区间或跨平台独立复制。

## 4. An Analysis of Multi-hop Iterative Approximate Byzantine Consensus with Local Communication（arXiv:2106.14312；引用追踪）

- §III–V：Relay-IABC 让节点用签名和邻居间逐跳转发消息；作者把直径为 D 的 D 轮通信视作一阶段有效全连接，再执行裁剪均值。文中理论分析针对其明示的故障上界、通信与签名假设，不是直接放宽任意部署中的所有共识限制。
- §VI：作者以 transition-matrix 收缩论证 Relay-IABC 每 3 个阶段可形成 scrambling matrix，并与基线 IABC 所需的图相关窗口比较；该渐近因子不是所有网络和故障模型下的无条件实测加速结论。
- §VII：经验部分是单一随机 Erdős–Rényi 参数设置（30 个诚实节点、14 个拜占庭节点）的 Python 仿真，用诚实节点状态标准差随迭代变化作图；未报告多随机种子不确定性、真实网络、消息/字节开销基准。§VIII 明确承认 flooding 通信开销很重。
- 与 2012 工作的关系：不是简单推翻拓扑充要条件，而是增加多跳中继和密码签名，改变每个迭代阶段可获得的信息，从而以更多通信换取稀疏/局部网络下的可行性与更快收敛主张。

## 跨论文可检验问题（不是已确认的全领域空白）

在统一同步、故障预算和相同终止误差下，对比单跳 IABC 与签名 Relay-IABC：分别在稠密/稀疏拓扑、不同直径、多个拜占庭策略与随机图种子上，报告达到误差阈值的轮数、墙钟延迟、总消息/字节、签名验证成本和失败率。预期可检验的权衡是：Relay-IABC 是否确实在稀疏图降低收敛轮数，同时把通信成本推高到使端到端延迟或能耗反而变差。

同批 DVFS 后续实验问题：用实际硬件功率计及公开 DAG，在相同 deadline、处理器 DVFS 状态和调度器预算下，按可回收 slack 分层检验算法增益；将仿真预测误差与硬件实测分开报告。
