# Full-text audit batch 53: query bounds, index advisors, and explicit world models

Updated 2026-10-12. This batch covers the three lexical-priority records in the frozen `databases × 2025–2026-through-10-11` cell. The papers concern theoretical cardinality bounds, industrial index tuning, and a multimodal explicit-world-model prototype; results are not pooled. All three selected arXiv-version PDFs were retrieved and reviewed. Later primary sources were checked where they affect the status or comparison set.

## Sampled papers

### 1. Efficient Algorithms for Cardinality Estimation and Conjunctive Query Evaluation With Simple Degree Constraints (arXiv:2504.02770v1; PODS 2025)

[arXiv full text](https://arxiv.org/abs/2504.02770); [ACM DOI 10.1145/3725233](https://doi.org/10.1145/3725233); local PDF: `data/fulltexts/arxiv/2504.02770v1.pdf` (23 pages); extracted text: `data/fulltexts/text/2504.02770v1.txt`.

The paper turns an exponentially sized LP for the polymatroid cardinality bound into a polynomial-size LP for “simple” degree constraints (`|X|≤1`). It also constructs a polynomial-length Shannon-inequality proof sequence of length `O(k²n²+kn³)`, which can reduce the proof-sequence component in the PANDA query-evaluation runtime. A new flow bound is polynomial-time computable for arbitrary degree constraints and no looser than the polymatroid bound or the earlier chain bound (with the paper's stated ordering/parameterization). Counterevidence to broad extrapolation is explicit: adding certain acyclic/FD constraints or permitting constraints with `|X|≤2, |Y|≤3` makes the polymatroid-bound computation as hard as the general case; computing it generally remains open.

Two current related results define useful comparison boundaries. PANDAExpress (2026) targets downstream query evaluation under arbitrary degree constraints and its abstract identifies PANDA's hidden polylogarithmic runtime factor as a practical weakness; it is not the same task as computing this paper's simple-constraint polymatroid bound. CorrBound (SIGMOD/PACMMOD 2026) adds inter- and intra-relation correlation information and evaluates estimation accuracy/time on benchmarks; it is a related, richer-statistics comparator, not a refutation of this paper's theorem.

### 2. Evaluating the Practical Effectiveness of LLM-Driven Index Tuning on Microsoft SQL Server (arXiv:2603.09181v3; PVLDB 2026)

[Microsoft Research publication record](https://www.microsoft.com/en-us/research/publication/evaluating-the-practical-effectiveness-of-llm-driven-index-tuning-with-microsoft-database-tuning-advisor/); [arXiv record](https://arxiv.org/abs/2603.09181); local PDF: `data/fulltexts/arxiv/2603.09181v3.pdf` (17 pages); extracted text: `data/fulltexts/text/2603.09181v3.txt`.

This study compares GPT-5 index recommendations with SQL Server's Database Tuning Advisor (DTA) using TPC-H SF10 and four anonymized enterprise workloads on SQL Server 2022. It measures actual execution time (five timed runs per configuration, median; individual runs capped at five minutes), not only optimizer cost. For each prompt the authors make five independent model calls and inspect the resulting configurations. Best-of-five GPT-5 recommendations can outperform DTA substantially on a meaningful subset of single-query cases, especially where optimizer cost estimates mislead DTA; but recommendation quality varies markedly across calls and workloads. On the constructed multi-query workloads, DTA is more stable/reliable overall, and directly adding LLM-suggested indexes to DTA's candidate pool often degrades results. Building/executing candidate configurations for performance validation can cost more than tuning itself. Thus “LLM beats DTA” is conditional on selection, query/workload shape, and validation budget—not a stable replacement result.

### 3. An Explicit World Model Based on Data-First Ontology: DaoQL Multimodal Storage Validation and Counterfactual Reasoning Evaluation (arXiv:2607.17269v1)

[arXiv full text](https://arxiv.org/abs/2607.17269); local PDF: `data/fulltexts/arxiv/2607.17269v1.pdf` (20 pages); extracted text: `data/fulltexts/text/2607.17269v1.txt`.

The paper gives formal sufficient conditions—independent rules, deterministic evaluation, and fixed conflict resolution—under which explicit, addressable state supports composable counterfactual evaluation. It then evaluates a Rust multimodal store and an explicit `Eval` path, while labeling the agent runtime and KVCache graph as future work. The reported comparison is DaoQL+GPT-4o versus GPT-4o alone across five domains: 50 underlying cases per domain, each paraphrased five ways (`250` underlying scenarios; `1,250` query instances). The paper reports composable-decomposability scores of 94% vs. 45%, but labels the result preliminary: full prompts, temperature, complete scoring procedure, and per-case failure logs are absent. Because paraphrases share an underlying scenario, uncertainty should be calculated at scenario level; treating 1,250 prompts as independent would overstate the effective sample size. Other boundaries: most microbenchmarks are 10K–100K scale, embedded-versus-client/server comparisons include deployment-shape differences, LDBC SNB uses a custom non-certified driver with 1.8 overall QPS, and the ANN test uses one synthetic dataset. The paper itself notes 16-connection throughput drops by about 40% and identifies concurrency work as future work.

## Bounded findings

1. **Query-bound tractability is a sharp input-class boundary.** The simple-degree theorem and proof-sequence construction are strong exact results, while small-looking extensions already recover general-case hardness. A practical follow-up should compare (a) simple-constraint polymatroid bounds, (b) the flow-bound relaxation, and (c) correlation-aware bounds such as CorrBound on identical real query/data snapshots. Report bound tightness, optimizer plan regret, evaluation time, memory, and required statistics; do not equate cardinality-estimator quality with end-to-end query speed. PANDAExpress addresses downstream evaluation cost, a distinct axis.

2. **Best-of-five LLM tuning is a candidate-generation result unless validation cost is charged.** The study supplies positive enterprise evidence for finding high-quality index configurations, but also shows high per-call variance, DTA's advantage on multi-query workloads, and expensive physical validation. A falsifiable systems question is whether a cost-aware controller can use estimated-cost gaps and limited actual runs to select among DTA and LLM candidates with better total (tuning + index build + workload) time at a fixed regression-risk budget than DTA alone or best-of-five. Compare first/median/best-of-k outputs and charge every trial.

3. **DaoQL's structural theorem and 1,250-prompt empirical score support different claims.** The formal sufficient condition concerns deterministic evaluation under explicit assumptions; the 94% empirical result is a preliminary comparison on 250 underlying scenarios with five paraphrases each, against one GPT-4o-only baseline. A replication should preregister prompts and scoring, blind evaluators, cluster uncertainty by underlying scenario, report exact per-case failures, and ablate explicit state, deterministic rules, and retrieval separately. This could falsify whether the measured gain comes from compositional state semantics rather than prompt, retrieval, or scenario-specific effects. No replication was performed here.

## Scope and limitations

These are three purposively selected lexical-priority papers from one frozen database-period cell. We did not reproduce LPs/theorems, rerun the index-tuning experiments, benchmark DaoQL, inspect source-code implementations, or exhaustively survey follow-ups. Findings are scoped research/evaluation leads and status notes, not claims of novelty or prevalence across databases research or the 198,690-paper corpus.
